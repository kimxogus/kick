# Product Registration Workflow

## 입력 수집

가능하면 아래 정보를 확보한다.

- 제품명
- 제품 URL 또는 데모 URL
- 대상 사용자
- 해결하려는 문제
- 주요 기능
- 경쟁 제품 또는 대체재
- 현재 설명 초안
- 스크린샷, 영상, 문서 링크

정보가 부족하면 추측으로 채우지 말고 `추가 확인 질문`에 남긴다.

## 분석 순서

1. 문제 정의가 명확한지 확인한다.
2. 대상 사용자가 좁고 구체적인지 확인한다.
3. 제품이 제공하는 변화를 사용자의 언어로 다시 쓴다.
4. 기능 나열을 사용자 이득으로 바꾼다.
5. 검증되지 않은 수치와 과장 표현을 제거한다.
6. 런칭 채널에 맞게 톤을 조정한다.

## 출력 템플릿

```markdown
## 핵심 kick point

1. ...
2. ...
3. ...

## 한 줄 소개

...

## 상세 소개 초안

...

## 추천 태그

- ...
- ...
- ...

## 시연 포인트

- ...
- ...
- ...

## 추가 확인 질문

- ...
```

## 작성 원칙

- 제품 제작자 관점보다 사용자 관점으로 쓴다.
- "혁신적", "최고", "완벽한" 같은 검증 어려운 표현은 피한다.
- 첫 문장에서 대상 사용자와 해결 문제를 드러낸다.
- 기술 구현보다 사용자가 얻는 결과를 앞에 둔다.
- 사내 행사 문구는 시연 가능성과 학습 포인트를 강조한다.
