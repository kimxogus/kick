# 0001. 프로젝트 문서와 ADR 체계 채택

- 상태: Accepted
- 날짜: 2026-06-09
- 관련 문서: `README.md`, `SPEC.md`, `ARCHITECTURE.md`, `TODO.md`, `ROADMAP.md`, `docs/README.md`

## 맥락

이 프로젝트는 사내 행사에서 1주 안에 MVP를 시연해야 한다. 초기 요구사항은 의도와 방향이 중심이며, 제품 범위와 기술 스택은 팀 논의로 계속 바뀔 가능성이 높다.

빠른 구현만 시작하면 요구사항, 설계, 결정 배경이 대화에 흩어져 후속 Codex/Claude 세션이나 팀원이 맥락을 잃을 수 있다.

## 결정

프로젝트 루트에 요구사항, 아키텍처, TODO, 로드맵 문서를 두고, 주요 제품/기술 결정은 `docs/adr/`에서 ADR로 관리한다.

구현 전에 관련 문서와 ADR을 먼저 갱신한다.

## 고려한 선택지

- 문서 없이 바로 구현: 초기 속도는 빠르지만 결정 배경이 사라진다.
- README 하나에 모두 기록: 시작은 단순하지만 문서가 빠르게 비대해진다.
- 별도 문서와 ADR 체계 사용: 문서 수가 늘지만 변경 추적과 후속 실행이 명확하다.

## 결과

- 새 세션도 `README.md`에서 핵심 문서로 이동할 수 있다.
- 미결정 사항은 `TODO.md`와 `Proposed` ADR로 남긴다.
- 확정된 의사결정은 ADR로 추적한다.
- 문서 유지 비용은 늘지만, 1주 MVP에서 반복되는 혼선을 줄인다.
