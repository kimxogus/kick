# 데모 페이지 명세 — 킥 (Kick)

> 콘테스트 데모용 웹사이트 페이지 구성. v1은 Skill + local data 기반, 백엔드/DB 없음.
> 제품 요구사항 단일 기준은 [SPEC.md](../SPEC.md), 심사 어필 전략은 [pitch.md](pitch.md) 참고.

## 페이지 목록 (총 5개)

| # | 페이지 | route | 한 줄 역할 |
| --- | --- | --- | --- |
| 1 | Home | `/` | 서비스 소개 + 진입 허브 |
| 2 | Weeklyboard | `/week` | 이번주 제품 + 좋아요 + 랭킹 |
| 3 | Products | `/products` | 전체 제품 탐색 + 검색 |
| 4 | Product 상세 | `/product/[id]` | Skill이 만든 런칭 페이지 |
| 5 | Contest | `/contest` | 콘테스트 목록 (기능 존재만 노출) |

> 등록 페이지는 없다. 등록은 Skill이 수행하고, 그 결과가 곧 Product 상세 페이지가 된다.

---

## 1. Home — `/`

서비스를 처음 보는 사람에게 "이게 뭐고 왜 새로운지"를 10초 안에 전달하는 페이지.

내용:

- **Hero**: 한 줄 정의 — "agent에게 말 한마디로 내 제품을 런칭한다, 킥(Kick)." + CTA(이번주 보기 / 탐색하기). 제작자 런칭 보조 CTA는 두지 않는다.
- **작동 방식 3스텝**: ① agent에게 "올려줘" → ② Skill이 정보 수집·콘텐츠 생성 → ③ 런칭 페이지 완성. 1번 스텝 보조 문구는 "한마디면 충분해요". (라이브 시연 안 될 때 이 섹션이 설명 백업)
- **스킬 안내 + 복사**: 3스텝 카드 아래에 `kick 스킬을 참고해서 내 제품 올려줘` 문구와 우측 복사 버튼. 누르면 그 문구가 클립보드에 복사된다.
- **이번주 하이라이트**: Weeklyboard 상위 제품 미리보기 카드 몇 개.
- **콘테스트 섹션**: 이번주 하이라이트 아래에 배치. 예정/진행중/종료 콘테스트 수를 표시하고 Contest 목록으로 이동.
- **뉴스레터**: 2단 구성.
  - 탐색하는 분께: 주간 큐레이션 구독 폼(이메일 입력).
  - 제품을 올린 분께: 피드백 리포트(좋아요·댓글·주간 랭킹 요약) 표시만. 이메일 입력 폼은 두지 않는다.
- (홈에는 제품 검색 input을 두지 않는다. 검색은 Products `/products`에서 제공.)
- 푸터: 서비스 소개, 콘테스트 링크.

어필:

- **참신성**: "마케팅을 사람이 아니라 agent가 한다"를 Hero+3스텝으로 즉시 각인.
- **완성도**: 빈 랜딩이 아니라 실제 제품 카드가 채워진 화면.

## 2. Weeklyboard — `/week`

킥의 발견 동선 핵심. 그 주에 올라온 제품을 날짜별로 보여주고 좋아요로 랭킹을 만든다.

내용:

- **주차 표시**: "이번 주 (날짜~날짜)" + 지난주 이동.
- **날짜별 제품 리스트**: 등록일 기준으로 묶음. 각 항목 = 썸네일·이름·한 줄 소개·카테고리·**좋아요 버튼(무제한)**·현재 좋아요 수.
- **주간 랭킹**: 좋아요 누적 상위 제품. 같은 페이지 사이드/상단에 배치 (별도 랭킹 페이지 만들지 않음).
- 좋아요 누르면 즉시 카운트·순위 반영 (local data 갱신).

어필:

- **완성도**: 등록 → 노출 → 좋아요 → 랭킹의 end-to-end 루프가 한 화면에서 동작.
- **실용성**: "오늘 만든 제품이 오늘 바로 경쟁한다"는 런칭 경험.

---

## 3. Products — `/products`

전체 제품을 탐색·검색하는 카탈로그. 콘텐츠가 풍부해 보이게 하는 페이지.

내용:

- **검색**: 제품명·한 줄 소개·태그 기준 (범위는 SPEC 미결정, 데모는 단순 텍스트 매칭).
- **카테고리 필터**: 카테고리 칩/탭.
- **제품 그리드**: 카드 = 썸네일·이름·한 줄 소개·카테고리·좋아요 수. 클릭 시 상세로.
- 정렬: 최신순 / 좋아요순.

어필:

- **완성도**: 시드 제품(기존 실제 제품을 킥 런칭처럼 연결)으로 카탈로그가 가득 차 보임.
- **품질 일관성**: 모든 카드가 동일한 포맷·품질 → 들쑥날쑥하지 않은 균일한 소개.

---

## 4. Product 상세 — `/product/[id]`

킥의 핵심 강점을 증명하는 페이지. Skill이 만든 **보장된 품질의 런칭 콘텐츠**가 그대로 보인다.

내용:

- **헤더**: 제품명·한 줄 소개·카테고리·제품 URL·좋아요 버튼.
- **카드뉴스**: Skill이 생성한 홍보용 이미지/슬라이드.
- **상세 소개글**: 핵심 가치, 해결하는 문제, 주요 기능.
- **홍보 카피 / 타겟 분석**: 대상 사용자별 메시지.
- **댓글**: 자유 소통. (창작자 1:1 메시지는 후순위 — 자리만 표시 가능.)
- 메타: 등록일, 소속 콘테스트(있으면).

어필:

- **참신성**: 사람이 안 쓴, agent가 한 번에 만든 결과물.
- **품질 강점**: "명령만 하면 이 품질이 보장된다" — 직접 홍보의 들쑥날쑥함과 대비되는 킥의 핵심 셀링 포인트.
- **완성도**: "딸깍 이상"을 눈으로 증명하는 페이지.

---

## 5. Contest — `/contest`

기능이 존재한다는 것만 보여주는 페이지. 개최/상금/마감 기반 등록이 가능하다는 그림만 전달.

내용:

- **콘테스트 카드 목록**: 제목·주최·상금(표시만)·마감일·참가 제품 수.
- "콘테스트 개최하기" CTA (실동작 없이 자리만, 또는 안내 모달).
- 상세 페이지·결제는 v1 범위 밖 — 목록 수준에서 멈춤.

어필:

- **확장성**: 단순 런칭을 넘어 "상금 걸린 콘테스트 플랫폼"으로 커질 수 있다는 비전.
- ※ MVP는 결제 미연동, 페이지/플로우만 (SPEC 확정 사항).

---

## 공통 요소

- **글로벌 네비**: 로고(홈) · Weeklyboard · Products · Contest · (뉴스레터 구독).
- **반응형**: 모바일에서도 깨지지 않게 — 완성도 점수 직결.
- **시드 데이터**: 빈 화면 금지. 기존 실제 제품을 시드로 채워 풍부하게.
- **데이터 출처**: 모든 페이지는 local data를 읽는다. 좋아요/댓글 쓰기도 local data 갱신.
